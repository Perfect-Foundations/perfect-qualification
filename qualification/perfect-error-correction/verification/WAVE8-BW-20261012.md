## Independent mathematical data

A new Python-standard-library-only oracle generates GF(7) evaluation-code
vectors in `scripts/bw_gf7_reference.py`. It uses exact modular polynomial
evaluation over distinct 0..5 evaluation points, without querying Rust.
The generator refuses to overwrite a frozen vector. It produced **16**
independent rows in `vectors/rs_bw_gf7_v1.tsv`, SHA-256
`ee8a732e3568b14145c99103b336526e82e955953ac2c7a3cfe22fcf8805f378`.
Each row explicitly records message coefficients, expected full codeword,
corrupted received coordinates, known erasures, and corrected positions.
Cases include zero/sparse messages, evaluation point zero, clean data,
one unknown error, mixed 1 error + 1 erasure at 2e+v=3, and three
erasures at parity bound, including changed values inside erased positions.

Existing independent GF(5), GF(16), GF(17) and Hamming mathematical
references are immutable and retained. GF(17) already covers n=16 and
two unknown errors/four known erasures. The production crate separately
runs a test-only exhaustive enumerator against Berlekamp–Welch on GF(5),
GF(7), GF(16), GF(17) at multiple legacy max_trials settings. The
frozen 16 GF(7) rows must **not** be counted as that differential corpus.

The public decoder still enforces the n<=16 field-parent validation and
the 2e+v<=n-k MDS correction radius. The original max_trials is a
